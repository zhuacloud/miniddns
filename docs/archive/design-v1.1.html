01目标与非目标

先把边界钉死。凡不在“目标”里的功能，一律不实现。

目标

维度要求
资源占用常驻 RSS ≤ 2.5 MB；idle CPU 严格为 0（阻塞在 netlink 上）；24 小时累计 CPU ≤ 2 s；静态二进制 ≤ 500 KB
响应性地址变化后 ≤ 3 s 内发出更新请求（debounce 默认 1.5 s）
正确性IP 未变化时**零写入请求**；只有变化/缺失时才写；幂等
可运维性只依赖 systemd + journald；日志结构化、可 grep；无状态文件
可移植性Debian / Alpine(musl) / OpenWrt 静态运行；无运行时动态库依赖（可选取）
可扩展性Provider 通过 vtable 插拔；v1 只实现 Cloudflare，接口必须为其后的 deSEC / RFC2136 / DNSPod 留位
安全证书必须严格校验，失败即中止（fail closed）；API token 不出现在命令行/日志/进程环境里

非目标 明确不做

  • 不做定时轮询。事件驱动 + 兜底 timer，绝无“每 N 分钟跑一次”的主循环路径。
  • 不做公网 IP 以外的 DNS 管理：不管理 MX/TXT/CAA，不做 zone 级操作，不做 DNSSEC/NS 配置。
  • 不支持 HTTP 代理、HTTP/2、TLS 1.3、客户端证书、AIA 抓取（见 §16 风险）。
  • 不写状态文件。远端记录是唯一的真相来源（source of truth）。
  • 不做 Web UI、不做多进程/多线程。单线程事件循环。

已冻结的技术选型

决策选择理由（不可再讨论）
语言C99无运行时开销，静态产物最小
地址变化检测netlink NETLINK_ROUTE 组播订阅 + 阻塞 recvmsg内核边沿触发，idle 时零 CPU 零唤醒；无 fork/exec/文本解析
TLSBearSSL（源码 vendor）纯 C、零依赖、默认无 malloc、无 I/O 绑定、MIT
HTTP自研 HTTP/1.1 最小客户端只用 Connection: close 定长/EOF 读取，不需要 chunked/ALPN/h2
JSONjsmn（单头文件 vendor）仅在需要从响应里取 record_id / 错误消息时使用
CA运行期解析 PEM bundle + mtime 重载常驻进程必须能跟上根证书轮换；编译期固化会静默失效

定时timerfd + ppoll与 netlink fd 同一事件循环，不引入信号处理

03部署布局与路径解析

自包含优先：程序目录下的 conf/ 是默认配置位置，缺失时才回落到系统 /etc。

发布产物布局（artifact root）

miniddns-1.0.0-x86_64-musl/
├── bin/miniddns                     # 静态二进制，ldd => not a dynamic executable
├── conf/miniddns.conf.example       # 模板；*注意* 不叫 miniddns.conf（见下）
├── ca/ca-certificates.crt           # 全量 CA 快照（兜底）
├── ca/README                        # 快照日期 + sha256 + 来源说明
└── doc/design.html                  # 本文档
为什么示例文件必须叫 .example

程序目录的 conf/ 优先级高于 /etc。如果包里自带 conf/miniddns.conf，用户放在 /etc/miniddns/ 的覆盖配置就永远不生效。因此：

  • 便携模式：用户自己 cp miniddns.conf.example conf/miniddns.conf → 程序目录配置生效
  • 系统打包模式：包内只放 .example → 自动回落到 /etc/miniddns/miniddns.conf
  • OpenWrt：同一机制，/usr/share/miniddns/conf/ 只放 example，用户配置在 /etc/miniddns/（overlay 可写）

artifact root 的确定方式

必须用 readlink("/proc/self/exe") 取真实路径，禁止使用 argv[0] 或当前工作目录（CWD 在 daemon 下不可信）。然后依次探测：

  1. dir = dirname(exe)：若 dir/conf 或 dir/ca 存在 → root = dir（扁平布局 miniddns + conf/ 同级）
  2. 否则若 dirname(dir)/conf 或 dirname(dir)/ca 存在 → root = dirname(dir)（bin/miniddns 布局）
  3. 否则 root = NULL（纯系统安装，全部走 /etc 与系统 CA）

配置文件的查找顺序

优先级路径说明
1--config <path>命令行显式指定；不存在即报错退出（不回落）
2<root>/conf/miniddns.conf程序目录自带配置（便携模式）
3/etc/miniddns/miniddns.conf系统安装位置

都找不到 → exit(1)，日志给出所有尝试过的路径。启动日志必须打印实际使用的配置文件路径（这是排障第一信息）。

2<root>/ca/ca-certificates.crt产物自带快照（兜底，见 §09）

内置快照优先于系统 CA 的代价

程序目录优先意味着系统 CA 更新不会自动生效。这不致命，因为 §09 的 notAfter 告警 + --check-ca 自检会把问题暴露在装机当天。若部署方希望跟随系统 CA，在配置里写 ca_bundle = /etc/ssl/certs/ca-certificates.crt 并把 ca/ 目录删掉即可。

文件权限校验 强制

打开配置文件、CA bundle、token 文件之前，必须 stat() 并拒绝以下情况（日志给出明确原因）：

st_uid != 0                      → "owner is not root"        (可用 --allow-non-root-owner 覆盖)
st_mode & (S_IWGRP|S_IWOTH)      → "group/world writable"     (无覆盖选项，硬失败)
S_ISLNK(st_mode)                 → 拒绝符号链接（用 O_NOFOLLOW 打开）
非普通文件                        → 拒绝 (S_ISREG)
大小 > 2 MiB (CA) / > 256 KiB (conf/token) → 拒绝

打开时必须 open(path, O_RDONLY|O_NOFOLLOW|O_CLOEXEC)。理由：能改写 CA bundle 或 token 的人即可 MITM 你的请求。

04配置文件规范

INI 子集：[section] + key = value。[record] 与 [provider] 可重复出现。

语法规则（解析器必须严格实现）

  • 行首行尾空白忽略；空行与纯注释行忽略；注释以 # 或 ; 起始（仅在行首，不做行尾注释，避免 token 里出现 # 被截断）
  • key 与 value 大小写不敏感（key）；value 保持原样并 trim 两侧空白
  • 不支持续行、不支持引号、不支持转义
  • 未知 key、未知 section、重复的非重复 key → 硬错误并给出行号（拼写错误必须当场发现，不能静默忽略）
  • 值中的 ${ENV} 不展开（避免 token 走环境变量）
  • 同一 [record] 内 (provider, name, type) 必须唯一，重复即报错

05运行时行为规格

单线程，两个 fd，一个 ppoll。没有任何周期性的“检查”。

05.1 进程生命周期

main()
 ├─ 解析 CLI
 ├─ 定位配置文件 → 解析 → 校验                    失败 → exit(1)
 ├─ 打开并 flock(lock_file, LOCK_EX|LOCK_NB)      已占用 → log+exit(0)
 ├─ 加载 CA（§09）                                 失败 → exit(1)
 ├─ provider 注册与 init（token 读取、配置校验）    失败 → exit(1)
 ├─ nl_open()：socket + bind(组) + 首次全量 dump    失败 → exit(1)
 ├─ install SIGTERM/SIGINT → signalfd 或 self-pipe
 ├─ 一次启动 cycle（reason=boot）                  IP 相同 → 零写入
 └─ loop:
      ppoll([nl_fd, timer_fd, sig_fd], 无限)
        · nl_fd 可读     → 读事件 → 标记 pending → 启动 debounce 窗口
        · debounce 到期  → cycle(reason=event)
        · timer_fd 到期  → cycle(reason=timer)
        · sig_fd 可读    → 清理后 exit(0)
为什么用 signalfd 而不是信号处理函数

异步信号会打断 ppoll/recvmsg/TLS 状态机，处理不当就是 EINTR 地狱。用 signalfd 把信号变成 fd 可读事件，退出路径唯一且可重入。必须 sigprocmask(SIG_BLOCK) 这三个信号之后再 signalfd。

05.2 netlink 监听

项规格
socketsocket(AF_NETLINK, SOCK_RAW|SOCK_CLOEXEC, NETLINK_ROUTE)
订阅组RTNLGRP_IPV4_IFADDR | RTNLGRP_IPV6_IFADDR；bind() 时用 nl_groups 位掩码（1 << (RTNLGRP_x - 1)）
顺序先 bind 订阅，再发 RTM_GETADDR dump。反过来会丢失两者之间的变化
dumpRTM_GETADDR + NLM_F_REQUEST|NLM_F_DUMP，nlmsg_seq 唯一；用 NLMSG_DONE/NLMSG_ERROR 终止；后续收到 nlmsg_seq 不同的事件即进入事件模式
接收缓冲setsockopt(SO_RCVBUF, 1 MiB)
读取每次 recvmsg 读 32 KiB，循环 NLMSG_OK 遍历。必须处理消息被拆分（NLMSG_DONE 之外的截断靠 buffer 大小避免）
关注的事件RTM_NEWADDR、RTM_DELADDR；RTM_NEWLINK/RTM_DELLINK 也订阅（RTNLGRP_LINK）以便接口 down/up 时重新评估
解码内容ifaddrmsg{family, prefixlen, flags, scope, index} + attrs：IFA_ADDRESS、IFA_LOCAL、IFA_FLAGS（32 位，优先于 ifa_flags 那 8 位）、IFA_CACHEINFO（valid/preferred lifetime）、IFA_LABEL
ENOBUFS必须：收到即 log warn + 重新执行一次 RTM_GETADDR 全量 dump 重建状态（说明内核丢事件，状态不可信）
权限不需要 root、不需要 CAP_NET_ADMIN
不要只靠事件维护状态

实现上应把“地址集合”当作可由 dump 重建的缓存，事件只用来触发重新评估。任何不确定状态（ENOBUFS、dump 失败、接口 down）都走“重新 dump”这条路径，而不是试图增量修补。

05.3 debounce 与触发源

一次地址变化会产生多条事件（tentative→preferred、deprecate、临时地址增删）。因此：

  • 收到任意事件 → 置 pending=1，并把 debounce deadline 设为 now + debounce_ms
  • debounce 窗口内再来的事件 → 重置 deadline（滑窗静默）
  • 窗口静默到期 → 执行一次 cycle，清 pending
  • 连续事件导致 deadline 不断后移时，设硬上限 max_defer = 10 × debounce_ms，超时强制执行（防止 ISP 抖动导致永不执行）
  • 兜底 timer 到期时若 pending=1，直接执行 cycle 并清 pending

05.4 cycle 伪代码（Provider 无关）

cycle(reason):
  log_info("cycle start reason=%s", reason)
  addrs = nl_rescan()                     # 全量 dump，不依赖事件增量
  for rec in records where enabled:
      if rec.type == A:   want = detect_ipv4(addrs)
      else:               want = detect_ipv6(addrs)
      if (!want):
          log_info("record name=%s type=%s action=skip reason=no-ip", ...)
          continue
      remote = rec.record_id
               ? { .id = rec.record_id, .known = false }
               : provider_discover(rec)       # 失败 → 记为 error，继续下一条
      if (!remote.found):
          if (!rec.create_if_missing): skip
          create → 成功则 log action=create
      else:
          if (ip_equal(remote.content, want, rec.type)):
              log_info("action=unchanged")
              continue
          patch_content(remote.id, want) → log action=update old=.. new=..
  log_info("cycle end ok=%d fail=%d duration_ms=%d")

逐条记录独立成败：一条记录失败不阻止其他记录继续。整体 cycle 结果用于计算重试退避。

05.5 重试与退避

情形动作
cycle 全部成功清空退避计数；等待下一次事件或 interval_fallback
任一记录失败按 retry_backoff 序列预约一次 retry（timerfd 重新设定为 min(backoff, interval_fallback)）
HTTP 429 且带 Retry-After用 Retry-After 覆盖退避（秒或 HTTP-date 两种格式都要支持）
E_TLS_CERT不快速重试（不会自愈）。按退避最大档重试，并保证日志打 error 级
E_TLS_TIME 且时钟未同步走时钟守卫路径（§05.6）
E_HTTP_4XX（除 429）配置/token 问题，不自愈 → 用最大退避档，log error

05.6 时钟守卫

OpenWrt 等无 RTC 设备开机时 time() 可能返回 1970。TLS 会以“证书尚未生效”失败，而 CA bundle 完全正常。规则：

  • 任何 HTTPS 请求前检查 time(NULL) < clock_guard_epoch
  • 命中则 log warn clock not synced，按 30 s 固定间隔重试，不消耗退避计数，不计入 cycle 失败统计
  • 同时区分日志：时间类错误用 err=tls_time，与 err=tls_cert 严格分开（否则排障会误判为 CA 坏了）

05.7 并发与域名解析

  • getaddrinfo() 是阻塞的。接受这一点：单线程下 DNS 慢会阻塞事件处理，但netlink 事件在内核 socket 队列里排队，不会丢失（§05.2 的 ENOBUFS 处理覆盖极端情况）。
  • SO_RCVTIMEO/SO_SNDTIMEO + connect_timeout_ms 保证单次请求有界。
  • runner 内不做任何 fork()。

  • （allow_temporary_ipv6=true 时豁免 TEMPORARY）
  • IFA_CACHEINFO.ifa_valid > 0（不为 0sec）
  • 不落在 §06.1 的不可发布前缀
  • 接口名通过 include/exclude 过滤

06.4 确定性排序（防抖动）

多个候选必须按与地址插入顺序无关的规则取一个，否则顺序变化会被误判为“IP 变了”：

  1. 地址字节序升序（v4 用 struct in_addr.s_addr 网络序转 host 后比较；v6 用 memcmp 16 字节）
  2. 取第一个

若配置了多个网卡且需要优先级，用 iface_include 只留一个接口——v1 不实现“按接口优先级排序”。

06.5 规范化比较

  • IPv4：格式化为 a.b.c.d（无前导零）后字符串比较
  • IPv6：展开为 8 组 16 位十六进制的规范形式再比较（2001:db8::1 与 2001:0db8:0:0:0:0:0:1 必须判定相等）。实现：解析成 uint16_t[8] 后逐元素比较，不要用 strcmp 处理 ::
  • 发布给 provider 的形式：RFC 5952 压缩小写形式（inet_ntop 输出即为该形式）
  • 从远端读回的 content 也要走同一套规范化后再比较

09CA 加载器

运行期解析 PEM bundle 为 br_x509_trust_anchor[]，支持 mtime 触发的重载与到期告警。

09.1 解析管线

read bundle (≤2 MiB, 整文件读入)
  └─ br_pem_decoder_init(dest_cb)
     br_pem_decoder_push(buf, len) 逐块喂入
     dest_cb 收到 "BEGIN CERTIFICATE"/"END CERTIFICATE" 边界
     └─ 累积 base64 → DER 缓冲区（每张证书独立）
        └─ br_x509_decoder_init(append_dn)
           br_x509_decoder_push(der, der_len)
           if (br_x509_decoder_last_error(&xc) != 0) → 记录“第 N 张证书解析失败”并跳过
           else:
             br_x509_pkey *pk = br_x509_decoder_get_pkey(&xc)
             深拷贝 DN 到 arena
             深拷贝 pk->key.rsa.{n,e}  或  pk->key.ec.{curve, point}
             ta[i].flags = BR_X509_TA_CA
             记录 xc.notafter_days / notafter_seconds
           ← DER 缓冲区此时可以释放

09.2 内存所有权（最容易写错的地方）

对象归属
PEM 文件内容本模块 malloc 一次，解析完立即 free
单张 DER本模块临时 buffer，**必须存活到 get_pkey 完成后**（br_ber_decoder 内部持有输入指针）
DN / RSA n,e / EC point必须深拷贝到本模块持有的 arena；get_pkey 返回的指针指向 DER，DER 释放后即悬空
br_x509_trust_anchor[]arena 的一部分；ca_reload() 时整块替换
不要保留全部 DER

整包约 200 KB / ~140 张，逐张解析后只留压缩后的公钥（RSA 2048 模数 256 B、EC 根仅 65 B），锚点集合约 20–50 KB。保留 DER 会让常驻内存多出 200 KB，等于白吃 10% 的内存预算。

09.3 arena 设计

  • 一次 malloc 一个大块（初值 64 KiB，不足则按 1.5× 扩容并 realloc），内部用 offset 指针
  • 重载时新旧并存：先构建新 arena，成功后原子替换指针，最后释放旧 arena（避免重载失败后无 CA 可用）
  • 锚点数量上限 512（防御性）

09.4 mtime 重载

  • 每次发起 HTTPS 请求之前 stat() CA 文件，比较 (st_mtime, st_size, st_ino)
  • 变化 → 重载；重载失败 → 保留旧锚点并 log error（切换发行版、文件被替换成坏文件时不能自杀）
  • 重载发生在“下一个请求前”这个天然安全点，不需要锁；struct mn_tls 每次请求都从 ca_current() 取锚点

09.5 到期告警

  • 解析时记录每张证书的 notafter（br_x509_decoder_context 的公开字段）
  • 启动日志固定打印：ca: loaded N anchors from PATH earliest_notAfter=YYYY-MM-DD source=bundled|system
  • 最早到期 < 90 天 → log warn：ca: anchor subject="CN=..." expires in D days (YYYY-MM-DD) — refresh ca/ bundle
  • 已过期锚点 → log error 并仍然加载（可能链上用的是别的锚点）

09.6 --check-ca 自检

只做 TLS 握手，不发送任何带 token 的请求：

  1. 按配置加载 CA，打印路径/锚点数/最早到期
  2. 对每个 provider 端点的 host 建 TCP + 完整 TLS 握手（含证书链验证 + 主机名校验）
  3. 对每个 ipv4_echo_url 的 host 同样握手
  4. 握手完成后立即关闭连接，不写任何字节
  5. 输出 check-ca: OK tls=1.2 cipher=ECDHE_RSA_AES128_GCM host=api.cloudflare.com 或失败原因
  6. 退出码：全部成功 0，任一失败 1

用途：打包验收、systemd ExecStartPre=（可选）、OpenWrt 包 postinst。这是防止“内置 CA 快照两年后静默失效”的唯一机制，必须实现。

-c, --config PATH指定配置文件；不存在即报错
-f, --foreground前台运行（默认行为；存在的意义是显式声明，供 systemd 使用）
-1, --once执行一次完整 cycle 后退出。退出码：0 全部成功/未变化，1 有失败
-n, --dry-run与 --once 类似，但不执行 update/create；discover 仍执行。日志中 action 变为 would-update
--print-ip只做 IP 探测并打印 ipv4=... ipv6=...（或 ipv4=none），不访问 provider，不加载 token
--check-config解析 + 校验配置，打印规范化结果（token 打码），退出
--check-caCA 加载 + 端点 TLS 握手自检（§09.6）
-l, --log-level L覆盖配置中的 log_level
-v, --version打印版本 + 编译信息（BearSSL 版本、jsmn、是否静态）
-h, --help用法
--allow-non-root-owner跳过“文件属主必须是 root”的检查（仅测试用）

默认（无参数）行为：以前台守护方式运行完整事件循环。所有诊断子命令都不获取 flock（可与运行中的实例共存）。

12.1 服务单元（单元模板）

源码位置 systemd/miniddns.service.in，三个占位符在安装时替换。构建产物中同时提供已替换好的 systemd/miniddns.service 供直接 cp 使用。

# systemd/miniddns.service.in  —— 安装后为 /etc/systemd/system/miniddns.service

# --- 加固 ---
NoNewPrivileges=yes

ProtectHome=yes
PrivateTmp=yes

两个绝不能加的项
  • PrivateNetwork=yes —— 会新建 network namespace，里面没有任何接口，永远收不到 rtnetlink 事件
  • IPAddressDeny=any / IPAddressAllow= 白名单 —— 用 cgroup BPF 过滤 socket 流量，会误伤 netlink/CONNECT 语义，不要引入

另外 RestrictAddressFamilies 里漏掉 AF_NETLINK 是本项目最容易踩的加固坑，症状是“进程启动即退出，日志只有 socket: Address family not supported”。

12.2 安装位置与可迁移性

程序用 /proc/self/exe 定位 artifact root（§03），所以单元的 ExecStart 必须指向真实二进制路径。两种方案，默认采用 A：

方案 A（推荐）：稳定符号链接 + 版本化目录

/opt/miniddns-1.1.0/{bin,conf,ca,doc}   # 版本化真实目录
/opt/miniddns -> miniddns-1.1.0          # 当前版本符号链接
/usr/local/bin/miniddns -> /opt/miniddns/bin/miniddns

# 单元里永远写这一行，升级/回滚都不改单元：
ExecStart=/usr/local/bin/miniddns --foreground
  • /proc/self/exe 会解析符号链接，得到 /opt/miniddns-1.1.0/bin/miniddns，root 定位依然正确
  • 升级 = 解包新版本目录 + 改一个软链 + systemctl restart；回滚同理
  • 此时单元的 ExecStart 与 PREFIX 解耦，可以用 @BINDIR@ 固定替换为 /usr/local/bin

方案 B：绝对前缀（单目录安装）

/opt/miniddns/{bin,conf,ca,doc}
ExecStart=/opt/miniddns/bin/miniddns --foreground

简单直接，但移动目录后必须重新生成单元。两种方案都已被 install.sh --prefix ... --link-bin 覆盖。

12.3 单元文件的随包分发与安装

产物中的路径用途
systemd/miniddns.service.in模板，含 @BINDIR@ @CONFDIR@ @DOCDIR@
systemd/miniddns.service已按默认 PREFIX=/opt/miniddns 替换好的成品，可 cp 到 /etc/systemd/system/
install.sh安装二进制/配置/CA/文档 + 生成并安装单元 + daemon-reload
# 方式 1：install.sh（推荐）
sudo ./install.sh --prefix /opt/miniddns --link-bin

# 方式 2：手工（默认前缀）
sudo install -Dm0755 bin/miniddns    /opt/miniddns/bin/miniddns
sudo install -Dm0644 ca/ca-certificates.crt /opt/miniddns/ca/ca-certificates.crt
sudo install -Dm0644 systemd/miniddns.service /etc/systemd/system/miniddns.service
sudo systemctl daemon-reload
sudo systemctl enable --now miniddns
install.sh 的三条硬要求
  1. 不自带 conf/miniddns.conf：只安装 conf/miniddns.conf.example；若目标已存在配置文件，绝不覆盖
  2. 不覆盖已有 token；--prefix 与 --link-bin 之外不提供任何会改动 /etc/miniddns/ 的选项
  3. 安装完成后打印下一步命令，不自动 enable --now（配置还没填，自动启动只会刷错误日志）

12.4 关于运行用户

默认以 root 运行 + CapabilityBoundingSet=（空）。此时进程实际无任何 capability，等效非特权，但保留了读 0600 token 文件的能力。若希望彻底非 root，单元中改用：

User=miniddns
Group=miniddns
# token 文件改为 0640 root:miniddns，并按需去掉 LoadCredential

此处提供 systemd/miniddns@user.service.d/override.conf 片段，供 systemctl edit 直接引用，避免手写出错。

12.5 不需要 timer 单元

兜底周期由进程内 timerfd 实现（interval_fallback），不需要 .timer。好处：boot 后的首次同步与事件合并逻辑只有一处代码、不依赖 systemd 的 timer 语义、也不会出现“service 正在跑而 timer 又拉起一次”。

12.6 OpenWrt：没有 systemd

OpenWrt 使用 procd。产物中额外提供 openwrt/files/miniddns.init，并在 §13.3 的 dist 布局中包含它。要点：

  • procd_set_param respawn 3600 5 5，procd_set_param command /usr/bin/miniddns --foreground
  • procd_set_param limits core="0 0"；不需要 _capabilities 参数
  • START=99（等 sysntpd 起来），USE_PROCD=1
  • procd 不提供 systemd 那套 hardening；因此程序内的 fail-closed 校验（§09/§03）是唯一的防线，不可绕过

16风险与未决问题

风险影响缓解
BearSSL 不支持 TLS 1.3低CF 同时支持 1.2；且每次新连接都有 ECDHE PFS。若 CF 将来强制 1.3，替换 tls_http.c 内部实现为 mbedTLS（接口不变）
BearSSL 无 AIA 抓取低依赖服务端随握手发送中间证书（公开 CA 均如此）；失败时日志明确为链构建错误
BearSSL 上游 2021 后基本冻结中代码稳定、无 malloc、攻击面小；已把 TLS 隔离在单一模块内，替换成本可控
内置 CA 快照过期中notAfter 90 天告警 + --check-ca + ca/README 记录快照日期
多网卡/多 IPv6 时选择不符合用户预期中确定性排序 + iface_include/exclude 手工收敛；--print-ip 可即时验证
阻塞式 TLS 期间事件处理延迟低内核队列缓冲事件；http_timeout_ms 有界；ENOBUFS 触发全量 resync
Cloudflare GET /dns_records 秒级缓存导致重复写低容忍；建议用户填 record_id 跳过 discover
私有 IPv4 被 API 拒绝中§06.2 在探测层拦截，绝不发出必然失败的请求

未决问题（v1 明确不做，记录在此）

  • 多实例：v1 用 instance + lock 文件支持“多份配置多进程”，但不在单进程内跑多套 provider 组（一个进程服务整个配置）
  • Zone 名自动解析为 zone_id：v1 要求显式填写 zone_id（避免额外权限与额外失败模式）。可用 curl 一次性查出后写进配置
  • 记录删除/清理（IP 消失时删除 AAAA）：v1 只跳过，不删除。理由是“删除”破坏性太强，且 IPv6 地址消失多数是瞬态
  • IPv6 前缀变化（RTNLGRP_IPV6_PREFIX）：v1 只订阅地址事件，不订阅前缀事件。前缀变化最终会体现为地址变化，延迟可接受。若要做“前缀一变立即动作”，加 RTNLGRP_IPV6_PREFIX 即可（接口已留位）

  • IP 不变时，24 小时内对 provider 的写请求数为 0
  • 产物中的 systemd/miniddns.service 可直接 cp 到 /etc/systemd/system/ 后 systemd-analyze verify 无报错，且启动后能收到 netlink 事件（说明 AF_NETLINK 未漏）
  • 私有/保留 IP 从不被发送到 provider
  • temporary/dadfailed 地址从不被发布
  • 任何证书错误都导致中止且不发请求，无降级路径
  • ldd build/miniddns 显示静态（静态目标）
  • MemoryPeak ≤ 6 MB 且 CPUUsageNSec/24h ≤ 2 s
  • journald 中 grep 'action=update' 能精确列出每一次真实变更
